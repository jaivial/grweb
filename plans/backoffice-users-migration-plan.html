Backoffice Users Migration Plan

Detailed implementation plan for migrating the route-based users/member backoffice implementation from /var/www/grweb/frontend/ into the new canonical project at /var/www/grweb/backoffice/.

Scope: plan only Source/reference: frontend Canonical app: backoffice PM routing required

Objective

Move the route-based backoffice users/member experience into /var/www/grweb/backoffice/, making it the canonical deployed backoffice. After migration, /var/www/grweb/frontend/ becomes source/reference only for these pages and must not be treated as the deployed backoffice.

  • [ ] Confirm /backoffice is the canonical deployed app served through the Cloudflare tunnel.
  • [ ] Port users list, role detail, member detail, and new member flows to backoffice/src/.
  • [ ] Fix frontend rule violations and invalid Hook usage before or during the port.
  • [ ] Align backend API behavior and failure reporting so the UI can trust responses.

Detailed Tasks

Frontend Migration Tasks

  • [ ] Treat /var/www/grweb/frontend/src/pages/backoffice/users/ as source/reference only; do not deploy it as the backoffice.
  • [ ] Compare source pages with existing /var/www/grweb/backoffice/src/pages/backoffice/users/UsersPage.tsx and preserve the better project-native patterns.
  • [ ] Create or update backoffice page modules for UsersPage.tsx, RoleDetailPage.tsx, MemberDetailPage.tsx, NewMemberPage.tsx, and index.ts.
  • [ ] Fix invalid Hook usage from /var/www/grweb/frontend/src/pages/backoffice/users/MemberDetailPage.tsx before or while porting so hooks are top-level, unconditional, and never inside callbacks/branches.
  • [ ] Replace local useState with atoms where state is required by project rules, using useAtomValue and useSetAtom.
  • [ ] Put all derived render structures, filtered lists, counters, labels, route params transformations, and display models behind useMemo.
  • [ ] Stabilize handlers passed to child components with useCallback.
  • [ ] Keep folder-per-component organization and split large files before they approach 800 lines.
  • [ ] Ensure every TSX/HTML tag in modified files has a unique semantic data-* attribute within its logical block.
  • [ ] Wire routes in /var/www/grweb/backoffice/src/app.tsx for users list, role detail, member detail, and new member.

Backend Contract And Reliability Tasks

  • [ ] Decide contract for GET /api/competition/{competicionId}/users: implement paginated/filterable backend response or formalize array response in /var/www/grweb/backoffice/src/api/client.ts and /var/www/grweb/backoffice/src/types/api.ts.
  • [ ] If backend pagination is selected, update /var/www/grweb/backend/GrCup.Api/Endpoints/CompetitionUsersEndpoints.cs and /var/www/grweb/backend/GrCup.Api/Services/UserManagementService.cs with page, pageSize, search, role, and status filters.
  • [ ] Fix invitation CTA generation in /var/www/grweb/backend/GrCup.Api/Services/EmailService.cs so user invitations use website_frontend_url via GetBackofficeLoginUrl().
  • [ ] Fix email-send failure reporting in /var/www/grweb/backend/GrCup.Api/Endpoints/CompetitionUsersEndpoints.cs so failed SMTP does not silently return success.
  • [ ] Move invalid role validation into endpoint try/catch or return a clean 400 error with the project error shape.
  • [ ] Verify authorization checks for list, create, update, delete, role switch, and competition assignment operations.

Rollback Plan

  1. Stop deployment if backend build, backoffice build, or permission smoke tests fail.
  2. Keep the existing deployed service untouched until the new /var/www/grweb/backoffice/ build is verified locally.
  3. If deployment fails, point service/tunnel back to the last known working build target and restore previous environment values.
  4. If API contract changes cause breakage, revert to the formalized array-response client path or restore prior backend endpoint behavior until pagination is ready.
  5. If invitation emails fail after changes, disable invite sending path or return explicit warning/failure while preserving created-user audit logs.
